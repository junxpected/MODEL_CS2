# Як робити внесок

Дякую за інтерес до CS2 Demo Analyzer. Перш ніж надсилати зміни, ознайомтеся з [Кодексом поведінки](CODE_OF_CONDUCT.md).

## Початок роботи

1. Створіть fork репозиторію та клонуйте його локально.
2. Створіть віртуальне середовище й установіть залежності:

   ```bash
   python -m venv .venv
   source .venv/bin/activate
   pip install -r requirements.txt
   ```

3. Створіть окрему гілку від `main`. Назва має коротко описувати зміну:

   ```bash
   git switch -c feature/імя-зміни
   ```

   Приклади: `fix/zst-decompression`, `feature/new-round-feature`, `docs/setup-guide`.

## Вимоги до змін

- Дотримуйтеся стилю Python (PEP 8), пишіть зрозумілі назви та короткі docstring для нових публічних функцій.
- Не додавайте demo-файли, персональні дані, токени або згенеровані моделі до Git.
- Оновлюйте README, якщо зміни впливають на встановлення, запуск або поведінку проєкту.

## Перевірка

Перед pull request виконайте щонайменше:

```bash
python -m py_compile parse_demo.py features.py train_pipeline.py
```

Якщо зміна стосується парсингу чи навчання, перевірте її на власній невеликій `.dem`-демці та вкажіть результат у pull request. Не завантажуйте сам файл демки, якщо не маєте права його поширювати.

## Pull request

1. Зробіть атомарні, зрозуміло названі коміти.
2. Відправте гілку у свій fork і відкрийте PR до `main`.
3. У описі PR вкажіть: проблему, що саме змінилося, як ви це перевірили та можливі обмеження.
4. Переконайтеся, що PR не містить зайвих згенерованих файлів або секретів.
5. Будьте готові відповісти на коментарі та, за потреби, оновити зміни.

Дякую за внесок!
